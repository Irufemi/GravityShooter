## 9. 将来的なアーキテクチャ拡張（AAAクラスへの技術的負債返済・最適化）
※ フェーズ1・2のリファクタリングにより商業レベルのアーキテクチャ（関心の分離・DODの基礎）は達成済み。さらなる「限界突破（AAA規模への対応）」を目指す場合の将来的な展望です。

- [ ] **真のDOD（ECS）を目指したメモリ連続化の徹底 (SoA / AoS)** (※1万個描画での60FPS達成によりパフォーマンス要件はクリアしたため、当面はデスコープ/保留)
  - 現在のマネージャー（DebrisManager等）は更新処理の一括化（バッチ処理）を実現しているが、データの保持自体は `GameObject` や `Component` のポインタ（`std::shared_ptr`）単位でヒープ上に散財している。
  - CPUのキャッシュヒット率を極限まで引き上げるため、これらを `std::vector<DebrisData>` のように完全に連続したメモリ領域にパッキングし、データ指向設計（Data-Oriented Design）をさらに突き詰める。
- [ ] **イベント駆動アーキテクチャ (Event Bus / Delegate システム) の導入**
  - 現在の死亡時処理（`onPlayerDied` など）は `std::function` を用いた直接的なコールバック登録を行っているが、システムが肥大化すると参照関係の管理が難しくなる。
  - Unreal Engine の `Delegate` や汎用的な `EventBus` システムをエンジン側に新設し、「イベントの発行（Broadcast）」と「購読（Subscribe）」によってシステム間を完全に疎結合にする（例：`Event_PlayerTakeDamage` や `Event_PlayerDied` を投げるだけで全UIやマネージャーが一斉に反応する設計）。
