# ゲーム仕様書 (Game Design Document)

## 1. プロジェクト概要
- **タイトル名:** Gravity Shooter (仮)
- **ジャンル:** ルート固定シューティング（3D奥スクロール形式）
- **開発環境:** C++ / DirectX12（自作エンジン `IrufemiEngine`）
- **コンセプト:** 
  『DEATH STRANDING』のような重厚で退廃的な空気感の中で、『グラビティデイズ』のような「周囲の物を重力で引き寄せてぶつける」アクションの爽快感を味わうゲーム。
- **ビジュアルテーマ:** 
  ダークで重厚感のあるエネルギー表現、サイバーパンク風の退廃的な都市や荒野。プレイヤー自身はスマートなエネルギー体を想定。

## 2. コアゲームプレイ＆操作仕様
ツインスティックシューティングの直感的な操作と、シンプルな入力によるアクション遷移を採用する。

### 2.1 移動（左スティック / アナログ入力）
- 自機は空間上の**見えないルート（スプライン曲線）に沿って自動前進**する。
- 左スティックの入力は、進行基準点に対するXY平面（画面の上下左右）の**相対的なオフセット移動**のみとする。これにより、地形への壁抜けバグを物理的に防止する。
- **疑似物理アクション挙動:** オフセット移動時には単純な座標加算ではなく、慣性（Acceleration）と摩擦（Friction）による滑らかで重厚なアクション挙動を適用する。
- **姿勢制御（重力ターン）:** 横移動の速度（Velocity）に応じて機体が自動的に進行方向へ傾く（ロール回転）バンキング処理を導入し、飛び回る疾走感を表現する。
- **浮遊感（Hovering）:** 何も入力していない待機時でも、サイン波によって常に機体がフワフワと上下に揺れるようにする。

### 2.2 エイムとマルチロックオン（手動マーキング方式）
- **キーボード/マウス操作**: レティクルを敵に合わせ「**右クリック**」を押すたびに、対象をキューに固定（マーキング）する。
- **ゲームパッド操作**: 右スティックでレティクルを操作（任意キーでリセット）し、専用ボタンで対象を固定する。
- **重複ロックオンと上限**: 同じ敵を複数回マーキングすることで「重複ロックオン」が可能。ロックオンの最大上限は「現在プレイヤーが保持しているガレキの数（最大5個）」に完全依存する。
- **サテライトUI**: 同じ敵に複数ロックした場合、1つ目のマーカーの周囲にサブマーカーがフワッと展開され、ロック数を視覚的に表現する。
- **エイム判定**: 遠くの誤爆を防ぐ「2D距離＋3D深度のスコアリング」と、壁裏を無効化する「レイキャスト遮蔽判定（Line of Sight / Raycast）」を実装。遮蔽物に隠れた敵への誤ロックを完全に遮断する。
- **個別部位へのマルチロックオン**: Bossなどの大型敵の場合、本体ではなく「周囲を旋回するシールド（装甲）」や「部位（ソケット）」それぞれを個別にロックオン対象とする。

### 2.3 重力スロー（一斉掃射とノーロック直進）
- ガレキの引き寄せは専用キー（**Eキー**）で行う。
- ガレキを保持した状態で「発射（**左クリック**）」を押すと、キューに固定された対象に向かって `0.15秒` 間隔でガレキが時間差で一斉に飛んでいく。
- **ノーロック直進撃ち**: マーキングせずに発射した場合、レティクルの向いている方向の奥の空間に向けて真っ直ぐガレキを飛ばす（偏差射撃対応）。
- **手動キャンセル**: 専用キー（**Rキー**）で現在溜まっているマーキングを瞬時に全クリアする。

### 2.4 ボス戦のレベルデザイン（進行と将来の拡張）
- **基本方針（レール座標系 相対追従ドッグファイト）**: ボス戦は『RailRelativeFollowerComponent』により、レール座標系上でプレイヤーの前方一定距離を維持しながら、プレイヤーの回避旋回に呼応してドッグファイトを展開する相対追従チェイスバトルを基本とする。外装装甲の破壊によって内部弱点コアが露出するマルチフェーズ設計を採用し、撃破シーケンスへと移行する。
- **将来の拡張構想（アリーナバトルへのフェーズ移行）**:
  - レール終点（行き止まり）に到達した場合、ボスが逃走をやめて反転し、プレイヤーの真正面に陣取る「最終決戦フェーズ」への移行を構想する。
  - この際、自機の強制前進（自動スクロール）はストップし、ホバーリングによる上下左右の回避行動のみで激しい弾幕を避け合う純粋な撃ち合い（アリーナバトル）となることで、1つの戦闘の中でドラマチックな緩急を生み出す。

## 3. 技術的最適化と実装要件（パフォーマンス要件）
処理負荷を極限まで抑え、見た目の派手さと爽快感を担保する「賢い騙し」を実装する。

### 3.1 見せかけの物理演算（処理負荷の削減）
- **引き寄せ・浮遊中:** 
  ガレキの引き寄せや浮遊中は、重力演算や地形とのメッシュコリジョンを完全に無効化する。
  浮遊の挙動は、自機を親としたローカル座標にて `sin` / `cos` 等を用いた時間経過のアニメーションで軽量に表現する。
- **投擲時:** 
  物理落下をさせず、ターゲットへのホーミング処理と簡易判定（Sphere等）に切り替えて確実に当てる仕様とする。
- **投擲時（ターゲットから外れた場合）:** 
  処理負荷を抑えつつ『グラビティデイズ』の手触りを実現するため、以下の2段階の判定で Object Pool へ回収する。
  1. **距離ベースのデスポーン:** 何も命中せず自機から一定距離（例: 1500ユニット）離れた場合、限界距離超過として回収する。
  2. **建造物（OBB）への衝突:** 背景の建造物を大まかなOBB（Broad-Phase）で覆い、接触時は回収する。将来的にはOBB接触時のみ詳細なポリゴン判定（Narrow-Phase）へ移行する設計とする。
  - **※回収時の演出 (VoxelParticle):** 限界距離での消去時、およびOBB接触時のいずれにおいても、単に消すのではなく **`VoxelParticle`** をエミット（放出）する。GPUの物理挙動（風や慣性）に合わせてガレキが空中で散るように表現し、重力場が崩壊したようなリッチな見た目を持たせる。

### 3.2 メモリ管理の厳格化とバリエーション管理
- ゲームループ中（毎フレームのUpdate内など）の動的なメモリ確保（`new` / `delete`）は厳禁。
- 弾、ガレキ、敵などの複数出現するオブジェクトは、C++テンプレート等を用いた**「Object Poolパターン」**で管理・再利用する。
- **ガレキのバリエーション管理（Prefab-Based Pooling）:**
  ガレキのモデル（岩、鉄骨等）ごとに異なるコライダーサイズやパラメータを持たせるため、各種ガレキを個別の「プレハブ（JSON）」としてエディタ上で作成・視覚的に調整する。`DebrisManager`はプレハブパスのリストを読み込み、種類ごとにObject Poolを事前生成してランダムに提供する設計とし、プログラムからのパラメータのハードコードを排除する。

### 3.3 データ駆動設計 (Data-Driven)
- ルートの制御点（Waypoint）や、敵・建造物の出現タイミング・座標はシーンにハードコーディングしない。
- JSONやCSV形式の外部ファイルでマップごとの「ウェーブ情報」を定義し、実行時にパースしてスポーンさせる設計とする。
- **環境・建造物管理 (`EnvironmentManager`):** 背景や障害物となる建造物もシーンへの直接配置は避け、`EnvironmentManagerComponent` が一元管理（プーリング・動的配置）する。Prefab Linking機構によりシーンファイルの肥大化を防ぎつつ、描画時は自動的にインスタンシング（バッチ描画）へすり替えることで、エディタの操作性と極限のパフォーマンスを両立したデータ駆動アーキテクチャを採用する。

### 3.4 空間分割と描画の最適化 (AAAアーキテクチャ)
- **Instancing & Conservative GPU Culling:** Sparse Set と Virtual Entity アーキテクチャにより最大10,000オブジェクトの大量生成・追尾ベンチマーク（CPU負荷0.066ms）に耐えうるスケーラビリティを実証。本編ゲームプレイにおいては、画面の視認性・敵弾把握・ゲームテンポを最優先し、数十〜100個規模のガレキが絶え間なく物理循環（吸引➔防御➔射出➔撃破ドロップ）する最適な密度にチューニングしている。
- **Dynamic BVH (動的AABBツリー):** エンジン側に導入される TLAS & BLAS 方式の動的BVHを用いて、大量のオブジェクトや弾の衝突判定を $O(N \log N)$ に最適化し、プロファイリングによる明確なパフォーマンス改善を提示する。

### 3.5 ポストプロセスとビジュアル（シェーダー演出）
- **Color Grading & Bloom & Volume Framework:** 重厚な空気感の演出や、エネルギーの青白い発光表現を実装し、サイバーパンク風のビジュアルテーマを確立する。また、AAA仕様の「動的 Volume Framework」を導入することで、インスペクタから拡張性の高いポストプロセスエフェクトの追加・管理を実現する。
- **空間の歪み（Screen Space Distortion）:** 自機や引き寄せたガレキの周囲の背景（オフスクリーンバッファ）をノーマルマップを用いて歪ませる屈折シェーダーを適用し、ブラックホールや陽炎のような「重力場の干渉」を視覚的に表現する。
- **流体的なオーラ表現（Aura Shader）:** 単なる半透明描画ではなく、Flow Map（フローマップ）によるUVスクロールや、頂点シェーダーでの波打ち（Vertex Displacement）を用いて、オーラを「渦巻くスマートプラズマ」のように生きた流体として表現する。
- **リムライトと深度フェード (Rim Light & Depth Fade):** キャラクターやガレキの輪郭をシアン色に強く発光（フレネル反射）させ、他オブジェクトとの交差部分を深度バッファを利用してフワッと消す（ソフトエッジ）ことで、実体のない重力エネルギーのオーラ感を強調する。
- **マルチレイヤー・アウトライン (バンド・デシネ風コミック表現):** 『グラビティデイズ』のビジュアル表現を踏襲し、単なる輪郭線ではなく「深度（シルエット）」「法線（オブジェクトの角や折り目）」「輝度（テクスチャの模様や落ち影）」の3つのG-Buffer情報から複合的にエッジを抽出する。これにより、3Dモデルでありながら手描きコミックのようなリッチな線画（描き込み）を実現し、ダークな世界観の説得力を高める。
