# 単元 01_01: カプセル化 (Encapsulation)

学校の授業資料「01_01. カプセル化」に基づくソースコードレビュー基準とアンチパターン一覧です。

---

## 1. カプセル化の基本概念
- **定義**: データ（メンバ変数）と、それを操作する手続き（メンバ関数）を1つのオブジェクトにまとめ、外部から直接見えないように隠蔽（情報隠蔽）すること。
- **目的**: 
  - オブジェクトの内部状態の不正な改変を防止する。
  - 内部実装の変更が外部のコードに波及しないようにする（疎結合・保守性の向上）。

---

## 2. アンチパターン 5選と判定基準

### アンチパターン①: public メンバ変数
- **概要**: `class` のメンバ変数が `public:` に配置され、外部から直接書き換え可能になっている。
- **判定基準**:
  - `class` 定義内で、静的定数（`static constexpr` / `static const`）以外の変数が `public:` に露出している。
- **改善方針**:
  - メンバ変数を `private:` に隠蔽する。
  - 必要に応じて適切な Getter / Setter アクセサを提供する。
  - 単なる受動的なデータ保持用オブジェクト（DTO）であれば、無意味に private にせず `struct` とする（アンチパターン④参照）。

---

### アンチパターン②: 非const参照を返す Getter
- **概要**: Getter メソッドが内部オブジェクトや配列（`std::vector` 等）への非const参照（`T&`）を返し、カプセル化が形骸化している。
- **判定基準**:
  - `Type& GetSomething()` のように非const参照を返す関数が存在する。
  - 外部コードがその参照を通じてメンバ変数を直接書き換えたり、コレクションの `clear()`, `push_back()`, `resize()` 等を実行できる状態。
- **改善方針**:
  - 読み取り専用アクセスには `const Type& GetSomething() const` を提供する。
  - 値変更が必要な場合は、`void SetSomething(const Type&)` などの明示的な Setter、または `UpdateSomething(...)` / `GetInstance(id)` などのドメイン操作メソッドを提供する。

---

### アンチパターン③: friend 宣言の乱用
- **概要**: エディタクラス、UIクラス、親マネージャークラス等に対して安易に `friend class` を指定し、private メンバを直接操作させている。
- **判定基準**:
  - `class` 定義内に `friend class Inspector...`, `friend class Manager...` 等が宣言され、private 境界が無力化されている。
- **改善方針**:
  - `friend` 宣言を削除する。
  - 外部クラスが必要とする操作・プロパティは、公開メソッド（Getter / Setter / 操作API）として正式にインターフェースを定義してアクセスさせる。

---

### アンチパターン④: 不必要なカプセル化（無意味な Getter/Setter）
- **概要**: 振る舞いを持たない単なるデータ転送用構造体（DTO / POD設定データ）なのに、無駄に `class` にして全メンバを private にし、単純な Getter/Setter を機械的に配置している。
- **判定基準**:
  - ビジネスロジックや状態不変条件を持たず、全変数が1対1のGetter/Setterで素通しされているクラス。
- **改善方針**:
  - 素直に `struct`（PODデータ構造体）として定義し、直接メンバアクセスを許可する。

---

### アンチパターン⑤: 神クラス / 単一責任の原則の破綻
- **概要**: 1つのクラスに過剰な責務や状態変数が集中し、カプセル化の境界が崩壊している。
- **判定基準**:
  - クラスのメンバ変数が数十個を超え、複数の異なる機能ドメイン（描画、物理、UI、音声等）が1つのクラスに混在している。
- **改善方針**:
  - 責務ごとにコンポーネントやサブクラスへ分割し、委譲（Delegation）を行う。

---

## 3. レビュー時のチェックリスト

- [ ] `class` のメンバ変数はすべて `private:`（または適切な継承がある場合のみ `protected:`）になっているか？
- [ ] 配列やコンテナ（`std::vector` など）への非const参照を直接返していないか？（`const` 版または個別要素アクセサになっているか？）
- [ ] 不要な `friend class` 宣言が存在しないか？
- [ ] 単なるパラメータ構造体が不要に `class` 化され、形骸化したアクセサで肥大化していないか？
- [ ] 内部ヘルパー関数（インデックス変換やメモリ解放処理など）が `public:` に露出していないか？
