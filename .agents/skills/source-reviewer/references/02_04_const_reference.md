# 単元: 02_04 引数のconst参照 (Pass by const-Reference)

学校の授業資料 `02_04. 引数のconst参照` に基づく、ソースコードレビュー基準・アンチパターン集、および引数受け渡し最適化ガイドです。

---

## 1. 単元の目的と背景

> **「個人就職作品のプロジェクトについて、自分のコード内の全ての関数引数で、サイズが64bitを超えるものをconst参照渡しに変更せよ。※無駄なコピー渡しを撲滅しよう」**
> 
> **AI判定用の補足**:  
> 値渡し + `std::move` によるコピーの最適化（ムーブセマンティクスによるシンク引数イディオム）を行っているケースについては値渡しをしてよい。

### なぜ引数の const 参照渡しが重要なのか？
C++ では、関数の引数はデフォルトで **「値渡し（コピー渡し）」** となります。
値渡しでは呼び出し元の変数が関数内の別変数として完全に複製されるため、次のような深刻なパフォーマンス低下とメモリ浪費を招きます。

1. **不要なメモリ確保・ヒープアロケーションの撲滅**:
   - `std::string` や `std::vector`、`std::unordered_map` 等の動的コンテナを値渡しすると、関数を呼ぶたびに要素全体のディープコピーとメモリの再確保（ヒープアロケーション）が実行され、フレームレートが著しく低下します。
2. **大きな数値型・構造体のコピーコスト削減**:
   - ゲーム開発で頻繁に受け渡される 3D 数学型（`Vector3` [12B], `Vector4` [16B], `Matrix4x4` [64B], `Quaternion` [16B]）や、衝突判定用ジオメトリ（`AABB`, `OBB`, `Sphere`）、演出設定構造体などは 64bit を超えるため、値渡しを繰り返すとスタック消費とコピー命令が蓄積します。
3. **読み取り専用の意図をコンパイラとチームに明示**:
   - `const` を付与することで、「この関数は渡されたデータを変更しない」という契約が成立し、誤った内部書き換えをコンパイル時に防止できます。

---

## 2. 引数渡し判定マトリクス (64bit 境界の厳格な使い分け)

ゲームプログラミングにおいて、**「なんでもかんでも const 参照にすれば良い」わけではありません**。  
x64 アーキテクチャでは参照の実態は **64bit ポインタ** です。そのため、引数のサイズによって明確に使い分ける必要があります。

| 引数の型・性質 | サイズ | 推奨される渡し方 | 理由・技術的背景 |
| :--- | :--- | :--- | :--- |
| **組み込みプリミティブ型** | `bool` (1B), `char` (1B), `short` (2B), `int` (4B), `float` (4B), `double` (8B), `size_t` (8B) | **値渡し (By Value)** | CPU レジスタ経由で直結転送されるため最速。参照にするとポインタ間接参照コストが発生し逆に遅くなる。 |
| **列挙型** | `enum`, `enum class` (1〜4B) | **値渡し (By Value)** | 整数型と同等。 |
| **ポインタ・スマートポインタの観察** | 生ポインタ `T*` (8B) | **値渡し (By Value)** | ポインタ自身が 64bit。ポインタの参照 `T* const&` は間接参照が2重になり無意味。 |
| **小さな構造体 (<= 8B)** | `Vector2` (8B) など 64bit 以下の POD 構造体 | **値渡し (By Value)** | レジスタに収まるため値渡しが効率的。 |
| **大きな数学構造体 (> 8B)** | `Vector3` (12B), `Vector4` (16B), `Matrix4x4` (64B), `Quaternion` (16B) | **`const T&` (const参照)** | 64bit を超えるため、コピーするよりポインタ転送（64bit）の方が圧倒的に軽量。 |
| **STL 動的コンテナ・文字列** | `std::string`, `std::vector<T>`, `std::wstring`, `nlohmann::json` 等 | **`const T&` (const参照)** | ディープコピーおよびヒープ確保の完全回避。 |
| **大きな独自構造体・クラス** | コライダー定義、設定用構造体、データテーブル | **`const T&` (const参照)** | メンバ全体のコピーコスト回避。 |
| **所有権の移動・保持 (Sink Argument)** | セッター等でメンバ変数へムーブ代入する場合 | **値渡し + `std::move`** | 授業補足に明記。左辺値・右辺値の両方に最適対応可能。 |
| **出力引数 (Out Parameter)** | 関数内で呼び出し元の変数を書き換えて結果を返す場合 | **非 const 参照 (`T&`)** または ポインタ (`T*`) | 呼び出し元へ結果を書き戻す意図を明確にする。 |

## 3. 減点・指摘対象となるアンチパターン (就職作品審査基準)

### ❌ アンチパターン①: 64bit を超える型の無駄な値渡し（Needless Copy）
- **症状**:
  `void SetPosition(Irufemi::Vector3 pos)` や `void LoadScene(std::string path)`、`void CheckHit(AABB box)` のように、8バイトを超えるデータが値渡しされている。
- **授業資料の警告**:
  呼び出すたびに無駄なコピー処理が発生し、パフォーマンスを無自覚に劣化させている。
- **改善案**:
  `void SetPosition(const Irufemi::Vector3& pos)`、`void LoadScene(const std::string& path)` のように `const &` を付与する。

---

### ❌ アンチパターン②: 64bit 以下の型に対する無意味な const 参照（Meaningless const-Ref）
- **症状**:
  `void SetSpeed(const float& speed)`、`void SetActive(const bool& active)`、`void SetType(const EntityType& type)`、`void SetTarget(Actor* const& target)`
- **授業資料の警告**:
  > **「このような無意味な const 参照は、理解せず使っていると判断されて就活上でも評価が下がるので注意」**
  
  x64 環境では参照は 64bit ポインタとして扱われるため、4バイトの `float` や 1バイトの `bool` を const 参照にすると、サイズが小さくならないどころか **参照解決（メモリアクセス・間接参照）のオーバーヘッドが増加して純粋に遅くなる**。
- **改善案**:
  `void SetSpeed(float speed)`、`void SetActive(bool active)`、`void SetTarget(Actor* target)` のように値渡しにする。

---

### ❌ アンチパターン③: 書き換えないのに const なしの参照渡し（Missing const）
- **症状**:
  `void RenderMesh(Mesh& mesh)`、`float CalculateDistance(Vector3& a, Vector3& b)`
- **授業資料の警告**:
  const なし参照渡しの関数は、呼び出し側に「この関数は中身を書き換えるんだな」と誤認させる。書き換えないなら必ず `const` をつけるべき。
- **改善案**:
  `void RenderMesh(const Mesh& mesh)`、`float CalculateDistance(const Vector3& a, const Vector3& b)` に修正する。

---

### ❌ アンチパターン④: ローカル変数の参照 return（Dangling Reference）
- **症状**:
  `const std::string& GetDefaultName() { std::string s = "Default"; return s; }`
- **授業資料の警告**:
  関数終了時に破棄されたローカル変数のメモリ跡地を参照することになり、致命的な未定義動作（クラッシュやメモリ破壊）を引き起こす。
- **改善案**:
  メンバ変数や静的変数など関数終了後も生存する変数の参照のみを返すか、ローカル変数なら値で return する。
